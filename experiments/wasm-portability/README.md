# WASM portability PoC

Experimental comparison only. These interfaces are not supported APIs and no
artifact is published. This branch builds on the PII fixes in PR #44.

## Scope

Both interfaces call the same six operations in `strapd-core`: PII detection,
PII masking, Base64 decoding, JSON sampling, UUID v7 generation and timestamp
formatting. The experiments live in a standalone Cargo workspace and are not
part of production builds or release workflows.

The only production manifest changes put existing browser dependency features
behind a **default-enabled** `browser` feature. Existing core/browser defaults
are preserved. The experimental workspace opts out with
`default-features = false`; the browser crate explicitly enables `browser`.

- `buffer/`: a core module with reusable owned input and result buffers. Four
  exported calls per text operation: resize/write input, execute, get output
  pointer and get output length. Error status is separate from output bytes.
- `component/`: typed WIT records/lists/results generated by wit-bindgen. The
  Preview 1 core module is also wrapped into a component using the standard
  reactor adapter. The Go harness manually implements the Canonical ABI for
  these six signatures; it is not a generated or general-purpose Go SDK.
- `host/main.go`: plain wazero, both core modules, real system clocks and
  `crypto/rand.Reader`. Owned WIT inputs are allocated using `cabi_realloc`;
  results are copied before `cabi_post_*` releases them. UTF-8 is validated
  before lifting a Canonical ABI string.
- `wasmtime_host.py`: Wasmtime's Python API, buffer module and typed component.
- `browser.mjs`: isolated local browser harness, both experimental paths and
  the existing browser bindings compiled with wasm-pack's web packaging.
  The actual WebApp keeps its existing bindings and integration.
- `src/bin/native.rs`: deterministic correctness oracle and core-only native
  timing baseline. Host results are compared against the real native core.

The buffer protocol accepts at most 8 MiB per input and keeps its buffers for
one instance. Callers must serialize access and copy output before the next
call. This is an experimental size/ownership convention, not a proposed public
ABI. UUID count is limited to 1–1024 in both experimental interfaces to avoid
unchecked allocation or the core helper's zero-count assumption.

## Reproduce

Requirements: Rust with the `wasm32-wasip1` and `wasm32-unknown-unknown` targets,
Go, Python, Node/pnpm, wasm-pack, wasm-tools, and the WebApp's installed
Playwright Chromium. Tool versions used are recorded in `RESULTS.md`.
Install wasm-tools from its official release for your platform; this does not
require a production repository script.

From the repository root:

```sh
rustup target add wasm32-wasip1 wasm32-unknown-unknown
make -C experiments/wasm-portability setup
make -C experiments/wasm-portability build WASM_TOOLS=/path/to/wasm-tools
make -C experiments/wasm-portability browser-baseline
make -C experiments/wasm-portability native
make -C experiments/wasm-portability go-test
make -C experiments/wasm-portability wasmtime-test
make -C experiments/wasm-portability browser-test
make -C experiments/wasm-portability fmt-check
make -C experiments/wasm-portability lint
```

`setup` downloads the pinned official Preview 1 reactor adapter to `build/`.
Override `REACTOR` to use an existing copy. The Python environment, Node
installation, Go caches and generated files stay under the experiment;
package managers also use their normal download caches. The browser runner
binds an ephemeral loopback port and closes its
browser/server after the checks. macOS sandbox restrictions may require running
Chromium and wasm-opt outside the agent sandbox.

Generated modules, bindings, fixtures, environments and Go caches are ignored.
Raw reference measurements are retained in `results/`; reruns write `build/`
and do not overwrite those reference results automatically.

## Verification and measurement boundaries

There are 69 oracle cases. They cover exact UTF-8 offsets, category selection,
compact JSON/grouped cards, invalid Base64, binary output, JSON errors,
nested sampling metadata, seeds above JavaScript's safe-integer range up to
`u64::MAX`, signed timestamp limits and UUID version/variant/current time.
All error paths are followed by successful operations. The raw buffer rejects
invalid UTF-8; the manual WIT-core host validates it before crossing the ABI.
The generated component and JS APIs accept typed strings.

Input sizes are 128 B, 1 KiB, 4 KiB, 20 KiB and 64 KiB. Clean/dense fixtures
repeat whole rows and space-pad to exact byte lengths, avoiding truncated PII.
Each size measures both detection and masking with all categories enabled.

Native timings call the core directly and include dropping its result. They
exclude all transport, text encoding, owned WIT input and host result objects.
After 20 warmups, 201 samples use sorted indexes 100/190 for median/p95.

Wazero receives prepared UTF-8 bytes, includes input copying, required UTF-8
validation, execution, result lifting/copying and guest cleanup, and uses the
same warmups/samples. Both interfaces produce Go objects of the same shape.
Compilation and instantiation are measured once separately after host WASI
setup; Go compilation/process startup are excluded.

Wasmtime receives Python text. Both timers include text encoding, execution,
result lifting/normalization and cleanup, with the same sample method. Dynamic
Python component bindings and handwritten buffer lifting differ in FFI calls
and object construction, especially for lists of records. These are host
integration measurements, not intrinsic ABI or engine speed comparisons.

Browser timers include JS text encoding, copies, operation, result lifting and
cleanup. After 20 warmups, 101 batches of ten calls use indexes 50/95. Browser
p95 is a percentile of batch means, not individual request tails. All browser
paths run in the same Chromium context with UTC timezone for parity. The
existing browser's binary decoder intentionally uses lossy text, and its UUID
wrapper has different validation: those cases are checked separately or
excluded rather than silently changing its behavior.

Buffer browser startup measures WASM compilation and instantiation separately,
excluding fetch. Generated component and existing browser startup measure
module load + compile + instantiate, including fetch and JS glue. These cold
measurements are different boundaries and must not be ranked as equivalent.

Go inspects linear memory after warmup and 1000 large repeated calls for both
core modules; browser checks the buffer module similarly. Wasmtime/component
and browser/component get repeated mixed-call/error recovery coverage, but the
public component APIs do not expose linear memory for the same heap-size check.
No whole-process RSS or production concurrency guarantees are claimed.
